审查覆盖 Runtime/Core、Runtime Host、Service/Tauri/Web/Distributed Hosts、Link、AgentKit、
Python Runner、Bot/Std plugins、Bot product、配置、协议镜像、前端包、文档和验证脚本。

## 发现与处置

### P1：Standalone resource client 静默丢失 provider invalidation（已修复）

`LocalResourceClient` 允许非 Ordered provider，但原先只返回
`ResourceProviderOutcome.result`，会丢弃 outcome 中独立于成功/失败的
`ResourceDescriptorInvalidation`。这违反资源生命周期契约；provider 若错误声明 ordering，或未来
新增非 Ordered invalidating provider，删除事实会静默丢失。

修复后 standalone client 遇到任何 invalidation 都返回结构化的
`ERR_REGISTRY_UNAUTHORIZED`/`host.plugin.resource_provider_unsupported` 失败，要求调用方使用 Host
actor resource client。新增回归测试覆盖这一行为。Host actor 的 `apply_resource_outcome` 仍是唯一
应用 invalidation 的路径。

### P2：legacy protocol class（保留，非冗余）

`legacy_protocol_class` 只为缺少显式 `protocol_classes` 的旧 manifest 提供导入默认值；现有测试覆盖
legacy accepted protocol 去重、默认 Domain 归类及 purity conflict 拒绝。它仍被 resolver 的兼容导入
路径使用，不能删除；新 manifest 仍要求显式 class 或经过规范化校验。

### P2：Agent deprecated facade（保留，非冗余）

`mutsuki-plugin-agent-{loop,context,prompt,session,memory-router,tool-router}` 的状态类型已迁移到
`mutsuki-agent-runtime`，但这些 crate 仍承载真实 plugin runner 和公开 plugin builder。bundle、
testkit、benchmark 与示例仍有消费者，因此不能按 deprecated 标记机械删除。当前 facade 仅重导出
迁移后的状态类型并保留 runner surface；后续应在下一个兼容周期完成消费者迁移后再删除。

### P2：ServiceRuntime 集中模块（记录，暂不拆分）

ServiceRuntime 同时协调 load plan、控制面、event source、runner supervisor、持久部署状态和资源
命令，但这些能力通过已有 owner crate 和明确 trait 接口装配。当前没有发现可在不改变生命周期所有权
的情况下安全拆分的独立边界；本次不做大规模拆 crate，避免引入新的 facade 或重复状态源。

## 未发现的越界

- Core 没有依赖具体 Host、Link、Agent、Bot 或 Std plugin。
- Protocol/wire package 没有依赖执行层；Python kit 未实现第二套 Core 或 provider endpoint。
- Link 未依赖业务 Host/plugin；插件到 Host 的依赖仍通过显式 integration package。
- Provider descriptor update/invalidation 仍由 Host actor 应用，未发现 receipt/output JSON 旁路。
- 产品 fallback 均有显式策略和 degraded/reject 观测；未发现把本地 fallback 伪装成远端成功的路径。

## 未执行边界

本次记录不宣称 hosted CI、真实账号、固定硬件性能、Windows/macOS GUI smoke 或独立 clean-clone
发布验收已通过；这些需要对应平台和凭据环境。
